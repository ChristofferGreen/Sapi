Ansor Broadens Tensor Program Search

Ansor automates tensor-program generation for deep learning by combining hierarchical sketches, complete-program search, learned cost modeling, and subgraph scheduling. The evaluation reports strong operator, subgraph, network, and search-time gains, with scope limited to static dense workloads and backend-supported instruction generation.

Section 07

Limits and Interpretation

The paper is explicit that Ansor is not a universal tensor compiler. It requires static known shapes, handles dense operators rather than sparse ones, and relies on backend compilers for target-specific instruction use. These limits mean the reported results should be interpreted for statically shaped dense deep learning workloads, especially where manual templates or vendor kernels leave optimization opportunities.

Claims Referencing This Source

  • Ansor automates tensor programs

    Ansor automatically generates high-performance tensor programs for deep neural network subgraphs from high-level computation definitions.

  • Ansor finds unreachable programs

    Ansor can find high-performance tensor programs outside the search spaces covered by existing search-based frameworks.

  • Scheduling reduces search time

    Ansor can match AutoTVM's performance with much less search time by jointly optimizing subgraphs and prioritizing important ones.

  • Ansor improves DNN execution

    Ansor improves end-to-end DNN execution performance on Intel CPU, ARM CPU, and NVIDIA GPU by up to 3.8x, 2.6x, and 1.7x relative to the best evaluated alternatives.

  • Static dense workloads constrain Ansor

    Ansor is limited to static known shapes, dense operators, and backend-supported platform-specific instruction optimizations.

  • Benchmarks favor Ansor

    Ansor outperforms existing search frameworks and manual libraries on single-operator and subgraph benchmarks across evaluated cases.

  • Cost model predicts throughput

    Ansor's learned cost model predicts tensor-program throughput accurately enough to guide search on the evaluated ResNet-50 dataset.

  • Scheduling targets bottleneck subgraphs

    Ansor's task scheduler allocates tuning time to subgraphs that are most likely to improve end-to-end DNN performance.

  • Hierarchy broadens search coverage

    Ansor's two-level sketch-and-annotation representation expands tensor-program search coverage beyond manual templates and early-pruned sequential construction.

  • Complete programs improve tuning

    Sampling complete programs and then fine-tuning them with evolutionary search and a learned cost model avoids inaccurate estimates of incomplete programs.

  • Aestimo compares workload performance

    Aestimo evaluates performance effects by running each feedback-directed binary on every workload input five times and comparing arithmetic and normalized geometric runtime summaries against the static binary.

  • Distributed architectures require compilers

    Distributed quantum computing requires compilers that can map arbitrary quantum algorithms to distributed architectures while accounting for network and communication constraints.

  • Empirical workflows improve compiler evidence

    Machine-learning-based compilation can make compiler optimization more evidence based because models must be grounded in empirical data that can be tested and independently scrutinized.

  • Training data limits learning

    Machine-learning-based compiler optimization is limited by the quality, representativeness, and cost of its training data and cannot by itself create legal transformations or derive legality analyses.

  • Features encode program behavior

    Program features provide the quantifiable representation that allows learning algorithms to reason about source code, intermediate representation, runtime profiles, or combinations of those properties.

  • Compiler automates DNA circuits

    The Seesaw Compiler automates the translation of feedforward digital logic into equivalent dual-rail and seesaw DNA strand displacement circuits, while producing simulation code and DNA sequences for construction.

  • Restoration compensates impurity

    Signal restoration and component tuning compensate for impurity in unpurified seesaw circuits, although leak reactions and sensitivity to synthesis and stoichiometry errors remain limiting concerns.

  • Single-input evaluation is unreliable

    Single-input performance evaluation of feedback-directed code transformations is unreliable because different evaluation inputs can prefer different training inputs.

  • Super-blocks isolate hot paths

    Super-blocks represent frequently executed paths as linear basic-block sequences that can only be entered at the first block but may exit from any block.

  • Supervision maps features to decisions

    Supervised learning for compiler optimization learns correlations between program-feature values and the optimization decisions that produce optimal or near-optimal empirical performance.

  • Benchmarks use separate inputs

    The experiments used separate profiling inputs and performance-measurement inputs across realistic C application programs.

  • Tail duplication forms super-blocks

    Trace selection followed by tail duplication converts frequently executed traces into super-blocks by removing control-flow entries into the middle of a trace.

  • Training inputs affect FDO

    Training input selection affects both the compiler decisions made for feedback-directed inlining and if-conversion and the measured performance of the resulting binaries.

  • WCC integrates static analysis

    WCC couples a C compiler to the aiT static WCET analyzer so that WCET data is produced transparently during compilation rather than by a separate manual post-compilation step.

  • Back annotation enables optimization

    WCC’s back-annotation raises assembly-level WCET information to source-level ICD-C structures, enabling source-level optimizations to use WCET, WCEP membership, execution frequencies, cache misses, code size, and spill-code data.

  • Weighted graphs expose hot paths

    Weighted flow graphs expose hot paths by attaching execution counts to basic blocks and taken counts to control-flow arcs.

  • Workloads exceed SPEC inputs

    The study's workloads extend beyond the standard SPEC CINT2000 inputs by adding representative application inputs, yielding 116 total inputs of which only 32 were provided by SPEC.
