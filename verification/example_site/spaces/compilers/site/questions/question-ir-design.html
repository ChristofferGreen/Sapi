What properties make an intermediate representation effective?

Active question | 1 source, 2 claims, 1 evidence item, 0 measurements

Current synthesis

The linked evidence suggests that an effective compiler representation separates high-level structure from low-level tuning choices, makes candidate structures enumerable through explicit derivation rules, and expands the reachable optimization space beyond hand-written templates. This answer is limited because it is grounded in one Ansor source about tensor-program search rather than broad IR literature.

Conclusions

  • For tensor-program search, a useful representation separates high-level program structure from low-level implementation decisions: Ansor uses sketches for structural choices and annotations for tile size, parallelism, unrolling, and vectorization. (strong support)
  • Explicit derivation rules make the representation operational: Ansor's listed rules construct candidate high-level structures from a computation graph instead of requiring a manual template for each operator. (strong support)
  • The evidence moderately supports the broader design lesson that an effective IR should broaden search coverage while preserving a tractable structure for enumeration and tuning. (moderate support)

Uncertainty

The synthesis is based on one linked source and one evidence record. It supports properties of Ansor's tensor-program search representation, but does not establish a complete theory of effective intermediate representations across all compiler domains. The evidence also notes limits: the listed rules are CPU examples, while GPU support uses additional target-specific derivations.
