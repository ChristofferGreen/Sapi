Where does machine learning improve compiler optimization decisions?

Active question | 1 source, 2 claims, 2 evidence items, 7 measurements

Current synthesis

In the linked Ansor evidence, machine learning improves compiler optimization decisions by acting as a learned cost model inside tensor-program search: it cheaply ranks complete candidate programs during evolutionary search, helping decide which candidates are promising enough to compile and measure on hardware.

Conclusions

  • Machine learning improves the candidate-selection step of compiler optimization in Ansor by predicting the fitness or throughput of complete tensor programs during evolutionary search, so the search can score many candidates before choosing programs for expensive hardware measurement. (moderate support)
  • The linked accuracy evidence supports the claim that Ansor's learned cost model was useful for ranking candidates in the reported ResNet-50 tuning experiment on Intel CPU: it used 20,000 measured programs for training and 5,000 for testing, with 0.079 RMSE, 0.958 R2, 0.851 pairwise comparison accuracy, and 0.624 recall@30. (strong support)
  • The evidence also indicates that Ansor uses machine learning after generating complete valid programs, rather than relying on estimates of incomplete programs, which supports better optimization decisions within its search loop. (moderate support)

Uncertainty

The synthesis is based on one linked source about Ansor. The strongest quantitative evidence is limited to a ResNet-50 tuning dataset on Intel CPU, and the linked evidence does not establish that the same cost-model accuracy or search benefit holds across all compiler domains, hardware targets, sparse workloads, dynamic shapes, or optimization frameworks.
