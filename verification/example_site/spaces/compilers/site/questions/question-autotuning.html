When is autotuning better than static compiler heuristics?

question-autotuning | status: active | 1 source, 4 claims, 3 evidence items, 14 measurements

Current synthesis

Autotuning is better supported when static or manually bounded compiler strategies cannot cover the useful tensor-program search space, especially for statically shaped dense deep-learning workloads where broader program generation and measured tuning can find faster operator, subgraph, and network schedules with less wasted search effort.

Conclusions

  • For the linked Ansor evidence, autotuning is most compelling when fixed templates or static search spaces miss high-performance tensor-program structures. Ansor's sketch-and-annotation design expands the search space, and the paper reports that many best programs it generated were outside existing search-framework spaces. (strong support)
  • The strongest linked performance case is for evaluated operator and subgraph workloads: Ansor is reported as best or tied for best across single-operator settings, with 1.1x to 22.5x gains over existing search frameworks, and 1.1x to 14.2x gains over manual libraries and other search frameworks on subgraphs. (strong support)
  • Autotuning is also favored when search effort can be allocated across many subgraphs rather than spent uniformly. In the linked Intel CPU network benchmark, Ansor matched AutoTVM with substantially fewer measurements and lower reported wall-clock time for the listed models. (moderate support)

Uncertainty

The answer is bounded by one linked source about Ansor. The evidence is strongest for statically shaped dense deep-learning tensor programs on the evaluated operators, subgraphs, hardware, and tuning budgets. It does not establish that autotuning always beats static compiler heuristics, sparse workloads, dynamic shapes, or mature vendor kernels outside the measured cases.
