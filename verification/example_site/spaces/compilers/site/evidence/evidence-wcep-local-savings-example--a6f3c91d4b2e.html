WCEP Local Savings Example

Evidence Excerpt

The source defines program WCET as the maximum path WCET over feasible paths and names the responsible path the WCEP. In the example CFG, the original WCEP has 205 cycles. Reducing one WCEP basic block from 80 to 40 cycles changes the global WCET to 195 cycles, so the global saving is 10 cycles rather than the local 40-cycle saving.

Page references: pp.253-254

Type: formal_argument

This formal example explains why WCET-aware compilation must reason globally about the worst-case execution path. It establishes that local timing gains do not automatically translate into equal whole-program WCET gains, because another path may become critical or partially absorb the local improvement.
