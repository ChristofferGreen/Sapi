Empirical Evidence as a Compiler Optimization Signal

Structure: wiki

Limits of Evidence

A synthesis page should compare profile counts, supervised labels, feature values, and performance measurements as related optimization evidence while noting that learned compiler models depend on the quality, cost, and representativeness of their training data.

Profiles and Learned Models

The profile-guided work grounds decisions in runtime counts and reports measured speedups for super-block optimizations. The machine-learning work generalizes empirical evidence into models that predict optimization choices from program features and separates learning from deployment inside the compiler.

Shared Evidence Model

Both sources treat compiler optimization as an evidence-guided decision problem. The profile-guided source uses execution counts and weighted flow graphs to focus classic C optimizations on frequently executed regions, while the machine-learning source uses empirical training data and learned models to choose optimization heuristics for unseen programs.

Claims Used by This Topic

  • Profiles guide classic optimizations

    Execution profiles integrated into an optimizing C compiler can guide classic optimizations toward the program regions that run most often.

  • Weighted graphs expose hot paths

    Weighted flow graphs expose hot paths by attaching execution counts to basic blocks and taken counts to control-flow arcs.

  • Profile optimization speeds benchmarks

    On the benchmark suite, profile-based super-block optimizations averaged a 1.15 speedup over the prototype compiler's globally optimized code.

  • Learning guides compiler choices

    Machine-learning-based compilation can use a model inside the compiler to choose compiler heuristics or optimizations for a given program according to learned evidence about what makes code faster, smaller, or less...

  • Training precedes deployment

    The machine-learning compiler workflow separates model learning from deployment: training data is used to learn a model, and the learned model is then inserted into the compiler to make predictions for new programs.

  • Supervision maps features to decisions

    Supervised learning for compiler optimization learns correlations between program-feature values and the optimization decisions that produce optimal or near-optimal empirical performance.

  • Empirical workflows improve compiler evidence

    Machine-learning-based compilation can make compiler optimization more evidence based because models must be grounded in empirical data that can be tested and independently scrutinized.

  • Training data limits learning

    Machine-learning-based compiler optimization is limited by the quality, representativeness, and cost of its training data and cannot by itself create legal transformations or derive legality analyses.

Insightful24 points
Maya Santoro

This synthesis makes the historical through-line surprisingly clear: both papers are trying to replace one-size-fits-all compiler guesses with measured evidence. Profile-guided optimization does it with execution counts on hot paths, while machine-learning compilation does it by learning from many measured optimization outcomes. The important commonality is not the tool, but the decision discipline.

Insightful25 points
Eli Okafor

The contrast between weighted flow graphs and learned feature vectors is useful. One makes a single program's runtime behavior visible to classic optimizations; the other compresses many programs and runs into a model that predicts future choices. Both are representations of evidence, but they differ a lot in how inspectable the resulting compiler decision is.

Insightful23 points
Lina Kovac

I would not read the machine-learning survey as making profile-guided optimization obsolete. The 1991 super-block work shows the value of precise local runtime counts, and the later ML framing shows how evidence can be generalized across workloads. They seem complementary: profiles can feed decisions directly, and profiling-style measurements can also become training labels or features.

Insightful24 points
Rory Chen

The limits section matters because evidence is only as good as its collection process. A profile-guided compiler can overfit to unrepresentative inputs, and a learned compiler model can encode the habits of a weak benchmark suite. The page is strongest when it treats measurements as signals that need validation, not as automatic truth.

Insightful26 points
Samira Haddad

One practical takeaway is that compiler evidence has a cost curve. Chang, Mahlke, and Hwu report large profiling overheads but modest average code growth, while Wang and O'Boyle emphasize training cost, sparse data, and feature quality. The engineering question is not whether evidence helps, but when the extra measurement cost buys enough optimization confidence.
