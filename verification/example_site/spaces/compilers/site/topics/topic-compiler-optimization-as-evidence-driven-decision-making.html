Compiler Optimization as Evidence-Driven Decision Making

Structure: wiki

Learning and profiling evidence

Machine-learning compilation separates model learning from deployment and relies on quantifiable program features, empirical labels, and careful feature selection. Profile-guided classic optimization similarly turns runtime behavior into compiler guidance, using execution profiles to focus conventional transformations on frequently run regions.

Limits and contrasts

The sources also show important limits. Machine learning depends on feature quality, representative data, and legality analyses supplied by compiler writers; profile-guided optimization depends on useful profiling inputs; WCC depends on safe static analysis and may trade timing improvements against code-size growth. These contrasts make the shared concept stronger rather than collapsing the methods into one technique.

Shared concept

The sources collectively support a topic about compilers as decision systems that use evidence about programs, executions, hardware, or timing models to select transformations. Machine-learning compilation uses empirical training data and program features to predict optimization choices, profile-guided optimization uses runtime counts to select hot super-block regions, and WCC uses static analyzer output to choose WCET-reducing transformations.

Static timing evidence

WCC broadens the evidence-driven idea from average-case performance to worst-case timing. It integrates aiT static analysis into compilation, back-annotates assembly-level WCET facts to source-level structures, computes safe loop bounds, and applies optimizations whose value is judged by their impact on the WCEP rather than by profiling input data.

Claims Used by This Topic

  • Empirical workflows improve compiler evidence

    Machine-learning-based compilation can make compiler optimization more evidence based because models must be grounded in empirical data that can be tested and independently scrutinized.

  • Learning guides compiler choices

    Machine-learning-based compilation can use a model inside the compiler to choose compiler heuristics or optimizations for a given program according to learned evidence about what makes code faster, smaller, or less...

  • Features encode program behavior

    Program features provide the quantifiable representation that allows learning algorithms to reason about source code, intermediate representation, runtime profiles, or combinations of those properties.

  • Feature reduction preserves signal

    Feature selection and dimension reduction are necessary in compiler-learning problems because larger feature spaces require more training examples and can contain redundant information.

  • Supervision maps features to decisions

    Supervised learning for compiler optimization learns correlations between program-feature values and the optimization decisions that produce optimal or near-optimal empirical performance.

  • Training data limits learning

    Machine-learning-based compiler optimization is limited by the quality, representativeness, and cost of its training data and cannot by itself create legal transformations or derive legality analyses.

  • Profiles guide classic optimizations

    Execution profiles integrated into an optimizing C compiler can guide classic optimizations toward the program regions that run most often.

  • WCC integrates static analysis

    WCC couples a C compiler to the aiT static WCET analyzer so that WCET data is produced transparently during compilation rather than by a separate manual post-compilation step.

  • Back annotation enables optimization

    WCC’s back-annotation raises assembly-level WCET information to source-level ICD-C structures, enabling source-level optimizations to use WCET, WCEP membership, execution frequencies, cache misses, code size, and...

  • Loop bounds become automatic

    WCC’s loop analyzer computes safe loop iteration bounds for most benchmark loops and exact bounds for the great majority, reducing reliance on manual flow facts.

I like that this topic groups three very different compiler feedback loops without flattening them into one method. Profiles, learned models, and WCET analysis all turn evidence into optimization choices, but they answer different questions: what ran hot, what has worked on similar programs, and what moves the worst-case path.

Eli Okafor

The comparison also makes feature representation feel central rather than incidental. Weighted flow graphs expose hot paths, ML feature vectors expose measurable program properties, and WCC back-annotation exposes timing facts at the level where transformations can use them. In each case, the compiler improves only after the evidence is put into a usable representation.

Lina Kovac

One useful contrast is that the evidence is not equally risky in all three settings. Profile-guided optimization can chase unrepresentative inputs, learned heuristics can inherit benchmark bias, and WCET-aware compilation must trust conservative static analysis. That shared dependence on evidence quality is probably the strongest caution for the whole page.

The WCC example usefully widens the discussion beyond speedup. If the objective is a safe upper bound, optimizing a frequent average-case path may be the wrong decision. That makes evidence-driven compilation less about one performance metric and more about making the compiler's objective explicit before choosing transformations.
