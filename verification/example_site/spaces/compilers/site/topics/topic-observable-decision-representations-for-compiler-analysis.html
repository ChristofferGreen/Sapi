Observable decision representations for compiler analysis

Structure: wiki

Section 1

This topic would cover how compilers expose internal optimization decisions or program behavior as comparable representations: Aestimo log vectors, profile-weighted flow graphs, ML feature vectors, and WCC back-annotation data.

Section 2

Aestimo isolates individual FDO transformations by logging decisions for one optimization and recompiling with only those logged choices, then compares decision variation through difference and alignment metrics. The same general concept appears in other sources as quantifiable program features for learning, execution counts attached to control-flow graphs, and WCET data raised from assembly analysis back into source-level compiler structures.

Section 3

The page should not imply these representations are interchangeable: Aestimo logs explain variation in FDO choices, ML features support prediction, and WCC annotations support worst-case timing optimization.

Claims Used by This Topic

  • Aestimo isolates FDO transformations

    Aestimo isolates individual feedback-directed optimization transformations by recording profile-guided decisions for one optimization and recompiling so that only that optimization reuses the logged decisions.

  • bzip2 logs diverge sharply

    For bzip2 on Itanium, inlining logs split into a high-alignment group with similar decisions and a low-alignment group with substantially different callsite choices and no universally inlined callsite.

  • Metrics quantify decision variation

    Difference and alignment metrics quantify how much training-input selection changes compile-time optimization decisions by converting optimization logs into comparable decision vectors.

  • Features encode program behavior

    Program features provide the quantifiable representation that allows learning algorithms to reason about source code, intermediate representation, runtime profiles, or combinations of those properties.

  • Supervision maps features to decisions

    Supervised learning for compiler optimization learns correlations between program-feature values and the optimization decisions that produce optimal or near-optimal empirical performance.

  • Back annotation enables optimization

    WCC’s back-annotation raises assembly-level WCET information to source-level ICD-C structures, enabling source-level optimizations to use WCET, WCEP membership, execution frequencies, cache misses, code size, and...

  • Weighted graphs expose hot paths

    Weighted flow graphs expose hot paths by attaching execution counts to basic blocks and taken counts to control-flow arcs.
