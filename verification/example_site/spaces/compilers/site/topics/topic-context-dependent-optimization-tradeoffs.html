Context-dependent optimization tradeoffs

Structure: wiki

Section 1

This topic would synthesize cases where an optimization is beneficial only under particular inputs, paths, hardware resources, or program contexts.

Section 2

Aestimo's bzip2 case shows training input materially changes inlining performance, with combined training, xml training, and best-case per-input FDO producing different gains. Machine-learning compilation frames the same issue through context-dependent choices such as thread coarsening. WCC and distributed quantum compilation add timing and resource-sensitive examples, where optimizing the wrong path or consuming limited communication resources can blunt or reverse expected benefits.

Section 3

The topic should emphasize conditionality rather than a universal ranking of optimizations, since the evidence spans conventional programs, WCET-oriented embedded compilation, and distributed quantum compilation.

    Remote CNOT execution consumes Bell-state resources and is limited by the number of available communication qubits, creating a tradeoff between communication capacity and data-qubit capacity.

    Static WCET reduction depends on optimizing the worst-case execution path, because reducing a noncritical path or a local block can leave the global WCET unchanged or only partly reduced.
